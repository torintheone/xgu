# Решения по механикам и устройству

Здесь записано, что выбрано там, где ТЗ оставило выбор. Любое решение можно пересмотреть; числа из симуляции меняются в `SimConfig.kt`.

## Этап 0 — каркас

| Тема | Решение | Почему |
| --- | --- | --- |
| Инструменты сборки | Gradle 9.7.1, Android Gradle Plugin 9.3.3, Kotlin 2.4.21; compileSdk и targetSdk 37 (Android 17), minSdk 26 | Самая новая связка, которую Kotlin официально поддерживает: Kotlin 2.4.21 проверен с AGP до 9.3.1 и Gradle до 9.7.0. AGP 9.3 уже умеет API 37. Kotlin компилируется встроенной поддержкой AGP 9, без плагина kotlin-android |
| Идентификатор приложения | `io.github.torintheone.petri` | Менять нельзя: с другим идентификатором Android считает приложение новым и не обновляет старое |
| Название и версия | `petri.appName` и `petri.version` в `gradle.properties`; при сборке по тегу версия берётся из тега | Одна константа на название, как требует ТЗ. versionCode = 1 + major·1 000 000 + minor·1 000 + patch, поэтому каждая следующая версия ставится поверх предыдущей |
| Единицы мира | Координаты в микрометрах, ось y направлена вверх, гравитация будет вдоль −y; время в игровых часах | Клетка массой 3,6 нг имеет диаметр около 25 мкм, чашка 1 мм — 1000 мкм: числа удобно читать |
| Шаг симуляции | 1 игровая минута (`STEP_HOURS`) | Совпадает с примером в ТЗ; подшаги для связей добавятся на этапе 1 |
| Скорость «Наблюдения» | 1 игровой час за 1 секунду (`OBSERVE_HOURS_PER_SECOND`) | Деление раз в 0,5–3 часа видно глазом как событие раз в несколько секунд. Подберём на телефоне |
| Скорость «Инкубации» | Без верхнего предела: шаги идут подряд, снимок для экрана — 60 раз в секунду | ТЗ требует максимальную скорость, которую тянет устройство. На пустой чашке возраст растёт очень быстро — это нормально |
| Отставание в «Наблюдении» | Не больше 4 шагов догоняния за кадр (`MAX_CATCH_UP_STEPS`), остальное отбрасывается | Медленное устройство будет идти медленнее реального времени вместо того, чтобы зависнуть |
| Диаметр чашки по умолчанию | 1 мм | Середина диапазона по ощущениям: помещается около 1000 взрослых клеток. Подберём при тестах этапа 2 |
| Передача снимков рендеру | Тройной буфер без блокировок (`TripleBuffer`) | Вариант двойной буферизации из ТЗ, при котором ни симуляция, ни рендер никогда не ждут друг друга |
| Свёрнутое приложение | Симуляция стоит, пока приложение не на экране | Экономит батарею; автосохранение при уходе в фон появится вместе с сохранением (этап 3) |
| Перерисовка | Только когда пришёл новый снимок или сдвинулась камера | В «Заморозке» экран не тратит батарею |
| Жесты | Один палец оставлен для инструментов; два пальца одновременно меняют зум и сдвигают вид; двойной тап — вся чашка | Как в ТЗ. Зум ограничен: от половины вписанной чашки до 40 мкм на короткой стороне экрана. Центр вида не уходит за край чашки, поэтому её нельзя потерять |
| Поворот экрана | Activity не пересоздаётся (`configChanges`), в альбомной ориентации вкладки слева | Сохраняется GL-контекст, симуляция не прерывается |
| Часы в интерфейсе | Подпись «h», как в ТЗ | Единица из оригинала и из ТЗ |
| Оформление | Всегда тёмная тема | Тёмный фон чашки задаёт тон всему приложению |
| Нативная библиотека из Compose | `libandroidx.graphics.path.so` исключена из APK (`packaging.jniLibs.excludes`) | Её приносит зависимость Compose `androidx.graphics:graphics-path`. Она нужна только для перебора сегментов `Path`, а приложение так пути не обходит: чашка рисуется через OpenGL. Так выполняется требование ТЗ «в APK нет папки lib/». Проверка в CI по-прежнему падает на любой другой нативной библиотеке |
| Выпуск релизов | Релиз с тегом `v0.<этап>.0` создаётся на странице Releases; workflow срабатывает и на пуш тега, и на публикацию релиза, прикладывает APK и подставляет описание из CHANGELOG.md | Облачная среда Claude может отправлять код только в свою ветку: пуш тега отклоняется (HTTP 403) |
| Подпись без ключа | Если секретов нет, release подписывается debug-ключом с предупреждением в логе и в описании релиза. Если ключ есть, но не хватает пароля или имени, сборка падает с понятной ошибкой | Сборка без ключа всё равно ставится начисто; а наполовину настроенный ключ лучше заметить сразу |

## Этапы 1–2 — физика, деление, питание

| Тема | Решение | Почему |
| --- | --- | --- |
| Размер клетки | Площадь пропорциональна массе: r = 6,588·√m мкм. Клетка 3,6 нг имеет диаметр 25 мкм | Растущая клетка заметно увеличивается, а при делении пополам площадь сохраняется |
| Шаг физики | 4 подшага на игровую минуту. Жёсткость пружин учитывается неявно (система 2×2 на клетку), вязкое трение тоже | Явная схема при жёстких связях «взрывала» колонию. Неявная остаётся устойчивой при любой жёсткости из настроек |
| Силы | Жёсткость пружин умножается на массу клетки | Лёгкие и тяжёлые клетки ведут себя одинаково, связи не рвутся от разницы масс |
| Связь (адгезин) | Пружина по линии центров, длина покоя = сумма радиусов + зазор до 10 мкм («Длина адгезина»). Точка крепления хранит угол на мембране; угловая пружина разворачивает клетку так, чтобы точка смотрела на партнёра | Так организм держит форму, которую задаёт геном, а не случайные толчки соседей |
| Разрыв связи | Если связь растянута больше чем на 45 мкм сверх длины покоя | Пинцетом можно оторвать клетку от организма |
| Наследование связей при делении | Связь матери достаётся тому потомку, с чьей стороны от плоскости деления лежит её точка крепления. Точка крепления сохраняет направление в мире | Прямая цепочка остаётся прямой, а угол потомка 15° даёт ровную дугу (проверено тестами) |
| Деление | Не чаще раза в 0,5 h. Порог массы деления 0 означает «делиться по возрасту», максимум означает «никогда не делиться». Деление тратит 0,3 нитратов | Простые правила, которые легко увидеть в превью генома |
| Пища | По умолчанию появляется в случайных местах и медленно дрейфует (плавное блуждание с «памятью» направления 15 мин). Клетка съедает частицу при касании. Частица, появившаяся прямо на фагоците, съедается сразу | Без дрейфа неподвижные фагоциты быстро съедали всё вокруг и голодали. С дрейфом колония живёт и растёт |
| Свет | Источник — точка на краю чашки, яркость спадает от неё по закону Гаусса; «Ширина света» 1 — ровный свет по всей чашке | Узкий луч заставляет колонию фотоцитов тянуться к источнику, как требует критерий этапа 2 |
| Расход | Каждый тип тратит свою массу в час (таблица в `SimConfig.baseCostPerHour`), всё умножается на 0,4. Солёность 0..1 меняет расход в 1,5..0,5 раза | Соотношения взяты из описаний типов, общий множитель подобран так, чтобы фагоциты на стартовой чашке росли |
| Обмен по связям | Связанные клетки выравнивают отношение «масса / приоритет» со скоростью 3 доли разницы в час; масса при этом не появляется и не исчезает | Критерий этапа 2: суммарная масса организма сохраняется (тест) |
| Стартовая чашка | 30 фагоцитов с геномом по умолчанию и пища на половину предела | Чашка сразу живая; пустую можно будет получить кнопкой «Стерилизовать» на вкладке «Среда» |
| Синтезатор | Сажает клетку массой 3 нг с текущим геномом в точку тапа | Взрослая клетка сразу может делиться |
| Пинцет | В «Заморозке» клетка переносится точно под палец. В остальных режимах её тянет к пальцу пружина, поэтому связанный организм тащится целиком | В замороженной чашке иначе ничего не двигалось бы |
| Подкормка | Тап по клетке добавляет 0,5 нг (не больше предела массы), тап по пустому месту кладёт частицу пищи | Один инструмент для обоих случаев из ТЗ |
| Диагностика | Тап выбирает клетку, камера сразу следует за ней; «Следить» включает и выключает слежение. Щипок или двойной тап выключают слежение | Двигать камеру и одновременно следить нельзя: пальцы победили бы камеру |
| Число видов | Сколько разных геномов сейчас живёт в чашке | До мутаций (этап 5) это число посаженных геномов |
| Сигналы в карточке | S1–S4 показываются, но до этапа 6 всегда равны 0 | Карточка сразу имеет вид из ТЗ |

## Этап 3 — редактор генома и генбанк

| Тема | Решение | Почему |
| --- | --- | --- |
| Файл генома | JSON: `formatVersion` первым полем, затем имя, начальный режим и 40 режимов со всеми параметрами, включая значения по умолчанию | Файл, которым поделились, значит одно и то же в любой будущей версии |
| Файл чашки | gzip(JSON) с полным состоянием: настройки, часы, генератор случайных чисел, клетки, связи вместе со списком свободных мест, пища, геномы, график. Значения, равные значениям по умолчанию, не пишутся | Загруженная чашка продолжает жить точно так же, как сохранённая (проверено тестом). Без значений по умолчанию геном в чашке занимает в несколько раз меньше места. Тест `FormatsTest` следит за значениями по умолчанию: если их поменять, тест напомнит поднять версию формата и написать миграцию |
| Миграции | Цепочка шагов «версия N → N+1» над JSON. Файл новее приложения не читается, а вызывает сообщение «обновите приложение» | Старые файлы всегда открываются в новых версиях |
| Неполные и битые файлы | Недостающие режимы генома заполняются новыми, лишние отбрасываются, значения вне диапазона зажимаются, неизвестные типы клеток становятся фагоцитами. Чашка с противоречиями (связь с несуществующей клеткой, NaN) не загружается | Чинится то, что можно починить без догадок. Сломанная чашка дала бы сбой позже, поэтому лучше сразу понятная ошибка |
| Имена файлов | Имя генома или чашки, записанное в Base64 (URL-вариант). Имя — до 40 символов | Любое имя, в том числе с «/» и эмодзи, работает в любой файловой системе. Сохранение под тем же именем заменяет файл |
| Запись файлов | Сначала во временный файл, потом переименование | Если телефон выключится посреди записи, старое сохранение останется целым |
| Превью роста | Отдельный мир с ростом 1 нг/h у каждой клетки, без расхода и смерти от голода, до 64 клеток, первая клетка «передом» вверх. Пересчёт через 300 мс после последнего изменения, целиком за 0–47 h | 48 часов колонии из 64 клеток считаются за 60 мс на компьютере, поэтому показывать по частям не нужно |
| Масштаб превью | Один на все часы, по самому большому кадру | Когда ползунок двигается, видно, как организм растёт |
| Сетка поиска соседей | Покрывает только прямоугольник вокруг клеток, а не всю чашку | Превью в чашке 3 мм ускорилось в 6 раз; в обычной чашке скорость не изменилась |
| Миниатюры в генбанке | Организм в момент, когда вырос до 64 клеток, но не позже 24 h; считаются в фоне при открытии | Отдельные файлы с картинками не нужны |
| Примеры в генбанке | Четыре генома записываются при первом запуске. Если их удалить, они не появятся снова | Новичку есть с чего начать, а генбанк остаётся под контролем человека |
| Синтезатор и редактор | Синтезатор всегда сажает геном из редактора. «Копировать геном» и «С микроскопа» кладут геном клетки в редактор | Один «текущий» геном вместо двух — проще понять |
| Автосохранение | При уходе в фон: чашка и геном редактора в папку `autosave`; при запуске они возвращаются | Требование ТЗ |
| Настройки приложения (DataStore) | Пока не используются: настроек приложения ещё нет | Хранилище подключим вместе с первой настройкой, чтобы не тянуть лишнюю зависимость |
