# Решения по механикам и устройству

Здесь записано, что выбрано там, где ТЗ оставило выбор. Любое решение можно пересмотреть; числа из симуляции меняются в `SimConfig.kt`.

## Этап 0 — каркас

| Тема | Решение | Почему |
| --- | --- | --- |
| Инструменты сборки | Gradle 9.7.1, Android Gradle Plugin 9.3.3, Kotlin 2.4.21; compileSdk и targetSdk 37 (Android 17), minSdk 26 | Самая новая связка, которую Kotlin официально поддерживает: Kotlin 2.4.21 проверен с AGP до 9.3.1 и Gradle до 9.7.0. AGP 9.3 уже умеет API 37. Kotlin компилируется встроенной поддержкой AGP 9, без плагина kotlin-android |
| Идентификатор приложения | `io.github.torintheone.petri` | Менять нельзя: с другим идентификатором Android считает приложение новым и не обновляет старое |
| Название и версия | `petri.appName` и `petri.version` в `gradle.properties`; при сборке по тегу версия берётся из тега | Одна константа на название, как требует ТЗ. versionCode = 1 + major·1 000 000 + minor·1 000 + patch, поэтому каждая следующая версия ставится поверх предыдущей |
| Единицы мира | Координаты в микрометрах, ось y направлена вверх, гравитация будет вдоль −y; время в игровых часах | Клетка массой 3,6 нг имеет диаметр около 25 мкм, чашка 1 мм — 1000 мкм: числа удобно читать |
| Шаг симуляции | 1 игровая минута (`STEP_HOURS`) | Совпадает с примером в ТЗ; подшаги для связей добавятся на этапе 1 |
| Скорость «Наблюдения» | 1 игровой час за 1 секунду (`OBSERVE_HOURS_PER_SECOND`) | Деление раз в 0,5–3 часа видно глазом как событие раз в несколько секунд. Подберём на телефоне |
| Скорость «Инкубации» | Без верхнего предела: шаги идут подряд, снимок для экрана — 60 раз в секунду | ТЗ требует максимальную скорость, которую тянет устройство. На пустой чашке возраст растёт очень быстро — это нормально |
| Отставание в «Наблюдении» | Не больше 4 шагов догоняния за кадр (`MAX_CATCH_UP_STEPS`), остальное отбрасывается | Медленное устройство будет идти медленнее реального времени вместо того, чтобы зависнуть |
| Диаметр чашки по умолчанию | 1 мм | Середина диапазона по ощущениям: помещается около 1000 взрослых клеток. Подберём при тестах этапа 2 |
| Передача снимков рендеру | Тройной буфер без блокировок (`TripleBuffer`) | Вариант двойной буферизации из ТЗ, при котором ни симуляция, ни рендер никогда не ждут друг друга |
| Свёрнутое приложение | Симуляция стоит, пока приложение не на экране | Экономит батарею; автосохранение при уходе в фон появится вместе с сохранением (этап 3) |
| Перерисовка | Только когда пришёл новый снимок или сдвинулась камера | В «Заморозке» экран не тратит батарею |
| Жесты | Один палец оставлен для инструментов; два пальца одновременно меняют зум и сдвигают вид; двойной тап — вся чашка | Как в ТЗ. Зум ограничен: от половины вписанной чашки до 40 мкм на короткой стороне экрана. Центр вида не уходит за край чашки, поэтому её нельзя потерять |
| Поворот экрана | Activity не пересоздаётся (`configChanges`), в альбомной ориентации вкладки слева | Сохраняется GL-контекст, симуляция не прерывается |
| Часы в интерфейсе | Подпись «h», как в ТЗ | Единица из оригинала и из ТЗ |
| Оформление | Всегда тёмная тема | Тёмный фон чашки задаёт тон всему приложению |
| Нативная библиотека из Compose | `libandroidx.graphics.path.so` исключена из APK (`packaging.jniLibs.excludes`) | Её приносит зависимость Compose `androidx.graphics:graphics-path`. Она нужна только для перебора сегментов `Path`, а приложение так пути не обходит: чашка рисуется через OpenGL. Так выполняется требование ТЗ «в APK нет папки lib/». Проверка в CI по-прежнему падает на любой другой нативной библиотеке |
| Выпуск релизов | Релиз с тегом `v0.<этап>.0` создаётся на странице Releases; workflow срабатывает и на пуш тега, и на публикацию релиза, прикладывает APK и подставляет описание из CHANGELOG.md | Облачная среда Claude может отправлять код только в свою ветку: пуш тега отклоняется (HTTP 403) |
| Подпись без ключа | Если секретов нет, release подписывается debug-ключом с предупреждением в логе и в описании релиза. Если ключ есть, но не хватает пароля или имени, сборка падает с понятной ошибкой | Сборка без ключа всё равно ставится начисто; а наполовину настроенный ключ лучше заметить сразу |
